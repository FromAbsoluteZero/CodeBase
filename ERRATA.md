# Errata

Corrections since first printing. Nothing listed yet for the current edition.

If a number in the book does not match a clean run at the pinned versions, please open an issue with the chapter, the block, and both figures.

## Format

**Chapter N, page P** — what the book says, what it should say, and when it was corrected.

## Corrections made before printing

These were found during production and are recorded here because the reasoning is useful, not because any printed copy contains them.

**Day 10 material, now Chapter 19** — a hand-computed information gain using entropy was compared against a decision tree left at its default Gini criterion. The two optimize different quantities and chose different splits; the text described the disagreement as a confirmation. Fixed by passing `criterion="entropy"`.

**Day 16 material, now Chapter 25** — the nested cross-validation demonstration printed an inner score *below* its nested score, which is the opposite of the effect the section exists to show. The sample was too large and too clean for optimism to appear. Fixed by reducing to 600 rows at `flip_y=0.15`, and the chapter now shows optimism growing with search size rather than at a single budget.

**Day 24 material** — a transfer-learning demonstration scored 0 of 2 on held-out examples, because those examples shared no vocabulary with the training documents. No representation could have bridged them. Fixed by giving each topic a consistent vocabulary.

**Day 8 material, now the Chapter 14 insert** — `make_classification` was called at its default of two clusters per class, which no linear boundary can separate, so log loss plateaued at 0.6237, barely below the 0.6931 of a model that has learned nothing. The claim being made was still true, but the output invited the conclusion that the code was broken.

**Day 7 material, now the Chapter 13 insert** — the text referred to how close the fitted weights were to the true values, which the program never printed. It now prints them.

**Chapter 30** — an early cache of Step 4's output was generated by literally concatenating every prior block's source and capturing all of stdout, which re-executed and re-printed Step 3's forward-pass output at the top of Step 4's own output block. The visible symptom was "predicted digit: 5" appearing twice in the built PDF. Fixed by writing `run_session.py`, which executes prior blocks with output suppressed and captures only the target block's own stdout. A second issue in the same chapter: `c6.py` had the accuracy figure `0.9722` hardcoded as a literal string rather than read from the computed variable, so it would have silently gone stale the first time an upstream number changed.

**Chapters 30 and 31** — both chapters originally threaded one shared, mutable `np.random.default_rng` through every code block in a chapter. This is fragile in two ways: concatenating blocks for shared session state also re-executes and re-prints every earlier block's own output (see above), and — more subtly — any change to which blocks ran before a given block shifts that block's random draws even when every block uses "the same" seed. Chapter 31 shipped once with numbers generated by an accidentally-incomplete block sequence, caught by a diff against the corrected, fully-sequenced run. Both chapters were rewritten so every function that consumes randomness takes an explicit `seed` parameter, with no code closing over shared mutable state. Every chapter from 32 onward was built this way from the first line.

**Chapter 43, Steps 3 and 4** — these are supposed to describe the identical twelve-week scenario from two monitoring angles (feature-distribution drift and model-performance drift). They were built with two independently-created random generators at the same seed value, but Step 4's generator skipped the 2,000-value `x_train` draw that Step 3 consumes before its own per-week loop, so the two "views of one dataset" were silently two different random realizations (final accuracy 0.4500 in one telling, 0.4760 in the other). Caught by checking that a number which should have matched across the two steps actually did. Fixed by having Step 4 explicitly advance its generator past the same unused draw Step 3 makes.

**Chapters 4, 8, 10, 12, 13, 14, 15, and 42 (reflowed from the original source)** — eighteen instances of "Chapter N's" in the original manuscript used U+2032, the prime symbol used for feet and minutes (as in 6′2″), instead of a proper apostrophe (U+2019), almost certainly a smart-quote autocorrect that misfired specifically after a digit. Caught by eye during a visual proofing pass on Chapter 42's opener, then traced across the full source and corrected everywhere it appeared with a scoped find-and-replace (only `digit + prime + s` → `digit + apostrophe + s`), not a blanket character substitution.
